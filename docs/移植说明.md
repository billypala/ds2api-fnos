# DS2API 移植飞牛 OS（fnOS）技术说明

> 本文档记录将 [ouqiting/ds2api](https://github.com/ouqiting/ds2api) v3.7.0 移植为 fnOS `.fpk` 应用包的设计决策，供后续维护参考。

## 1. 选型：Docker 应用

| 方案 | 结论 | 理由 |
|---|---|---|
| **Docker 应用** ✅ | 采用 | ds2api 原生支持 Docker，改造面最小；Go 静态二进制 + React 产物固化进镜像，一次打包覆盖 x86/ARM；容器隔离天然满足 fnOS 权限最小化 |
| Native 应用 | 备选 | 需 amd64/arm64 交叉编译 + 自建进程管理；资源占用最小、可走统一网关，但维护成本高 |

## 2. 关键配置

### 2.1 manifest（`app/manifest`）

```ini
appname=ds2api
version=3.7.0
source=thirdparty
platform=all
service_port=5001
checkport=true
ctl_stop=true
desktop_uidir=ui
desktop_applaunchname=ds2api.admin
```

- `platform=all`：包内无平台二进制，但**镜像必须支持目标设备架构**。
- `ctl_stop=true`：允许应用中心启停，`cmd/main status` 返回容器状态。
- 桌面入口指向 `/admin` 管理台，`allUsers=false` 仅管理员可见。

### 2.2 Docker Compose（`app/app/docker/docker-compose.yaml`）

```yaml
services:
  ds2api:
    image: ouqiting/ds2api:latest
    container_name: ds2api
    restart: always
    user: "0:0"
    network_mode: host          # 关键：代理桥 SOCKS5 需直落宿主
    volumes:
      - "${TRIM_PKGVAR}/config.json:/data/config.json"
      - "${TRIM_PKGVAR}/data:/app/data"
    environment:
      - PORT=${TRIM_SERVICE_PORT}
      - DS2API_CONFIG_PATH=/data/config.json
    env_file:
      - "${TRIM_PKGVAR}/.env"   # 管理密钥注入
```

**为什么必须 host 网络**：上游官方 compose 强制 `network_mode: host`。代理桥（Mihomo，一号一 IP）的 SOCKS5 监听（10801 起）直接落在宿主机，bridge 网络/端口映射隔离会导致 `Connection Refused`。host 模式下监听端口由 `PORT` 环境变量控制（= `TRIM_SERVICE_PORT` = 5001）。

### 2.3 数据持久化与首启

| 宿主机（TRIM_PKGVAR） | 容器内 | 内容 |
|---|---|---|
| `config.json` | `/data/config.json` | DeepSeek 账号 / API Key / token 持久化 |
| `data/` | `/app/data/` | WebUI 调用记录等运行数据 |
| `.env` | env_file | `DS2API_ADMIN_KEY` 管理密钥 |

`cmd/install_callback` 逻辑：

1. `mkdir -p ${TRIM_PKGVAR}/data`
2. 若 `config.json` 不存在，从 `${TRIM_APPDEST}/docker/config.example.json`（即包内 `app/app/docker/config.example.json`）复制
3. 管理密钥：优先取向导变量 `ds2api_admin_key`，未提供则 `head -c 18 /dev/urandom | od -An -tx1 | tr -d ' \n'` 随机生成，写入 `${TRIM_PKGVAR}/.env`

### 2.4 桌面入口（`app/app/ui/config`）

```json
{
  ".url": {
    "ds2api.admin": {
      "title": "DS2API 管理台",
      "icon": "images/icon_{0}.png",
      "type": "iframe",
      "protocol": "http",
      "port": "5001",
      "url": "/admin",
      "allUsers": false,
      "control": { "accessPerm": "readonly" }
    }
  }
}
```

### 2.5 安装向导（`app/wizard/install`）

- `ds2api_admin_key`（password，**必填**，min: 8）：管理台密钥，直接注入到 compose environment（见 2.3）。
- 端口固定 5001（host 模式无需映射），如需可配置需引入 wizard 端口变量并在 compose/入口中联动。

## 3. .fpk 容器格式

`.fpk` 真实格式为 `gzip(tar(...))` 嵌套压缩：

- 外层 tar：`app.tgz` + `cmd/`（9 个生命周期脚本）+ `config/`（privilege/resource）+ `ICON.PNG` + `ICON_256.PNG` + `manifest` + `wizard/`
- `app.tgz`：`app/` 目录整体打成的嵌套 tar.gz，**内部路径剥掉 `app/` 前缀**（直接 `docker/`、`ui/` 顶级）

因此生命周期脚本中访问包内资源用 `${TRIM_APPDEST}/docker/config.example.json`（而非 `app/docker/...`）。

## 4. 生命周期脚本约定

| 脚本 | 行为 |
|---|---|
| `cmd/main` | `start`/`stop` 交给应用中心（docker-project），`status` 用 `docker inspect -f '{{.State.Running}}' ds2api`；运行 exit 0，未运行 exit 3 |
| `cmd/install_callback` | 生成 config.json / .env（见 2.3） |
| 其余 `install_init`/`upgrade_*`/`uninstall_*`/`config_*` | 保持 `exit 0`（Docker 应用由应用中心管理） |

## 5. v3.7.1 关键修复（init 容器解耦时序）

v3.7.0 在 fnOS 上报 `env file /vol1/@appdata/ds2api/.env not found`。

**根因**：compose 引用 `env_file: ${TRIM_PKGVAR}/.env` 和挂载的 `config.json`，均由 `cmd/install_callback` 创建。但 fnOS 启动 Docker 项目的时序**不保证** install_callback 先于 `docker compose up`，导致 compose 启动时找不到文件。

**修复**：引入 **init 容器**（alpine）从包内 target 模板复制 config.json 到 PKGVAR，ds2api 通过 `depends_on: service_completed_successfully` 在 init 完成后启动，完全解耦时序。

```yaml
services:
  init:
    image: alpine:3.20
    restart: "no"
    volumes:
      - "${TRIM_PKGVAR}:/data"
      - "${TRIM_APPDEST}/docker:/tmpl:ro"
    entrypoint: ["/bin/sh", "-c"]
    command:
      - |
        set -eu
        mkdir -p /data
        if [ ! -f /data/config.json ]; then
          cp /tmpl/config.example.json /data/config.json
        fi
        chmod 666 /data/config.json
  ds2api:
    image: ouqiting/ds2api:latest
    network_mode: host
    volumes: ["${TRIM_PKGVAR}:/data"]
    environment:
      - DS2API_ADMIN_KEY=${ds2api_admin_key}    # wizard 必填变量直接注入
    depends_on:
      init: { condition: service_completed_successfully }
```

**`DS2API_ADMIN_KEY` 注入方式变更**：
- v3.7.0：通过 `env_file: ${TRIM_PKGVAR}/.env`（依赖 install_callback）
- v3.7.1：通过 compose `environment` + wizard 必填变量 `${ds2api_admin_key}`（fnOS 将 wizard 值作为环境变量提供给应用服务/容器进程）

## 6. 注意事项与风险

1. **源仓库转私密**：上游 2026-08-15 21:00 转私密仓库，已锁定 v3.7.0 本地备份。
2. **镜像架构**：确认官方镜像多架构；ARM 设备需自建 buildx 镜像并改 `image:` 字段。
3. **镜像加速**：国内拉取慢时配置 Docker 镜像加速器（`/etc/docker/daemon.json`）。
4. **许可证合规**：AGPL-3.0 需保留；逆向工具属性仅限学习研究，勿商用/违规使用。
5. **端口冲突**：`checkport=true` 在启动前校验 5001 是否被占用。
6. **wizard 密钥安全**：用户输入的管理密钥以环境变量形式传给容器进程，**不写入任何持久文件**；卸载后即丢失（重装需重新设置）。
